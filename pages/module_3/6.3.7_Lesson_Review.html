6.3.7 Lesson Review - Q&A

Q1. A video streaming service prioritizes speed over guaranteed delivery. Which Transport layer protocol is most likely used?

  • User Datagram Protocol (UDP)
  • Transport Layer Protocol (TCP)
  • File Transfer Protocol (FTP)
  • Internet Control Message Protocol (ICMP)

Speed over guaranteed delivery = UDP. Video streaming prioritizes low latency and continuous flow - dropped frames are acceptable but retransmission delays are not. TCP adds latency via retransmissions. FTP is an Application layer file transfer protocol. ICMP is used for diagnostics (ping, traceroute).

Q2. Which best describes why TCP is considered a "connection-oriented" protocol?

  • It uses encryption to secure data transmissions and prevent unauthorized access
  • It assigns random port numbers to ensure multiple applications can communicate simultaneously
  • It prioritizes speed over reliability, making it suitable for time-sensitive applications
  • It establishes a connection using a three-way handshake and ensures reliable data delivery

TCP's three-way handshake (SYN, SYN-ACK, ACK) formally establishes a connection before data flows, after which ordered reliable delivery is guaranteed. TCP has no built-in encryption (that is TLS/SSL). Ports are assigned systematically, not randomly. Prioritizing speed over reliability describes UDP.

Q3. Why does the Transport layer use port numbers in network communication?

  • To distinguish between applications communicating on the same device
  • To identify the physical address of the destination device
  • To ensure data is routed to the correct network
  • To encrypt data for secure transmission

Port numbers allow multiple applications to send and receive simultaneously on the same device (e.g. port 80 for HTTP, port 25 for SMTP). Physical (MAC) addresses are a Link layer concern. Routing between networks is the Internet layer's job. Encryption is handled by TLS/SSL, not port numbers.

Q4. You've installed DNS on a Windows server. Which port must be opened on the firewall to allow clients to access it?

  • 143
  • 110
  • 123
  • 53

Port 53 is the well-known port for DNS. Port 143 = IMAP. Port 110 = POP3. Port 123 = NTP (Network Time Protocol).

Q5. A client sends packets to a web server on port 80 but the server does not respond. What is the most likely cause?

  • The client device has an incorrect IP address
  • The server is using a different port for HTTP communication
  • The Transport layer protocol being used is UDP instead of TCP
  • The server's MAC address is not configured correctly

Packets are reaching the server (confirmed by packet analyzer) but it is not responding -- the web service is likely configured on a non-standard port. An incorrect client IP would prevent packets from arriving at all. HTTP uses TCP, and the packets are already arriving. MAC addresses are hardware-assigned and not manually configured.

Q6. A client sends SYN, the server responds SYN-ACK, but the client never sends the final ACK. What is the most likely cause?

  • The client's TCP connection is being blocked by a firewall, preventing the completion of the three-way handshake
  • The client's application is using an outdated protocol that does not support the three-way handshake
  • The server's port number is incorrectly configured, causing the client to fail to respond
  • The server is using UDP instead of TCP, which does not require a three-way handshake

SYN sent, SYN-ACK received, but the final ACK never goes out - a firewall blocking outbound ACK packets is the classic explanation. The client clearly supports the handshake (it sent the SYN). The server responded correctly so its port is fine. The SYN/SYN-ACK exchange is TCP-specific; UDP has no handshake.

Q7. A video conferencing app uses a connectionless protocol with minimal overhead and occasionally drops frames or has slight audio delays. What conclusion can be drawn?

  • The application uses SSH, which is unsuitable because it is designed for secure remote access, not real-time communication
  • The application uses TCP, which is unsuitable because it prioritizes reliability over speed
  • The application uses HTTPS, which is unsuitable because it is designed for secure web browsing
  • The application uses UDP, which is suitable because it prioritizes speed and can tolerate minor data loss

Connectionless with minimal overhead = UDP. Dropped frames and audio delays are the expected tradeoff for real-time video - minor loss is acceptable to avoid retransmission latency. SSH is TCP-based and connection-oriented. TCP is connection-oriented, not connectionless. HTTPS is an Application layer protocol, not Transport layer.

Q8. Which scenario best demonstrates the appropriate use of UDP?

  • A video streaming service that prioritizes speed over guaranteed delivery of every data packet
  • A remote server login session requiring authentication and reliable data transmission
  • A secure online banking transaction requiring encryption and acknowledgment of data delivery
  • A file transfer process where missing packets would result in corrupted files

UDP is ideal when speed matters more than perfection. Remote login (SSH) requires reliable delivery - use TCP. Banking requires reliability and security - use TCP + TLS. File transfers where missing packets corrupt the file require TCP. Video streaming can tolerate minor loss and benefits from UDP's lower latency.

Q9. An email protocol stores messages on the server, syncs across multiple devices, and keeps messages until explicitly deleted. Which port does this protocol use?

  • 21
  • 110
  • 143
  • 80

Server-side storage, multi-device sync, messages kept until deleted = IMAP (Internet Message Access Protocol), which uses port 143. Port 21 = FTP. Port 110 = POP3 (downloads and deletes from server, opposite of IMAP). Port 80 = HTTP.

Q10. Which layer of the TCP/IP protocol stack is responsible for assigning port numbers to network applications?

  • Transport Layer
  • Application Layer
  • Internet Layer
  • Link Layer

Port numbers are a Transport layer function - TCP and UDP both use ports to multiplex traffic between applications. The Application layer uses port numbers but does not assign them. The Internet layer handles IP addressing and routing. The Link layer handles framing and physical transmission with no concept of ports.
