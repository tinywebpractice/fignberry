7.1.11 Network Monitoring Servers

SNMP (Simple Network Management Protocol)

Framework for managing and monitoring network devices. The network management system polls agents at regular intervals and displays information and trap alerts for administrator review.

Versions
SNMPv1 and v2 should NOT be used due to security vulnerabilities. SNMPv3 is preferred as it supports authentication between the management system and enrolled devices.
Ports
UDP/161 (device queries), UDP/162 (trap notifications).

SNMP Components

Component Description
Network Management System (NMS) Central system that polls agents, collects MIB data, and displays alerts for the administrator.
Managed Devices Switches, routers, servers, and other SNMP-compatible network devices being monitored.
Agent Process running on a managed device. Maintains the MIB and can send trap notifications to the NMS.
MIB (Management Information Base) Database maintained by an agent. Holds activity statistics for the device (e.g., frames per second on a switch).
Trap Agent-initiated alert sent to the NMS when a notable event occurs (e.g., port failure). Thresholds are configurable per metric.

Syslog

De facto standard protocol and software for collecting event logs from distributed systems. A log collector aggregates event messages from multiple devices (routers, switches, UNIX/Linux servers, workstations) to a single storage location. Can also be configured to run status and alerting dashboards.

Port
UDP/514 (default)
Severity Levels
info, notice, warn, error, critical, alert, emergency

Syslog Message Format

Component Description
PRI Code Calculated from facility + severity level.
Header Contains timestamp and hostname.
Message Part Tag (source process) + content (application-dependent format).

Port Reference

Protocol Port Purpose
SNMP UDP/161 Device queries (NMS polls agents)
SNMP Trap UDP/162 Agent-to-NMS trap notifications
Syslog UDP/514 Log forwarding to collector
