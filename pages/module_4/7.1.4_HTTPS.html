7.1.4 Hypertext Transfer Protocol Secure (HTTPS)

SSL and TLS

SSL (Secure Sockets Layer)
Developed by Netscape in the 1990s to address HTTP's lack of encryption and authentication. Widely adopted but now superseded.
TLS (Transport Layer Security)
Developed from SSL; ratified as a standard by the IETF. Current replacement for SSL. Provides encryption and authentication for application protocols.
DTLS (Datagram Transport Layer Security)
TLS adapted for use with UDP. Most commonly used in VPN solutions.

HTTPS

HTTPS = HTTP + TLS. Encrypted traffic is sent over TCP/443 instead of the unencrypted TCP/80.

The "S" suffix pattern applies broadly: if a protocol acronym ends in "S" (HTTPS, SMTPS, LDAPS, FTPS, etc.), TLS/SSL is providing the security.

Digital Certificates and Key Pairs

Certificate Authority (CA)
A trusted third party that issues digital certificates. The client must trust the CA for the certificate to be valid.
Digital Certificate
Installed on the web server. Uses encrypted data to prove the server's identity to the client. Contains the server's public key.
Public Key
Distributed to clients via the digital certificate. Used to set up the encrypted tunnel.
Private Key
Kept secret on the server only. Required to decrypt tunnel contents. Without it, the encrypted session cannot be read or altered by a third party.
Cipher Suite
A set of cryptographic algorithms agreed upon by the client and server within TLS to establish the encrypted tunnel.

Browser Indicators

  • URL begins with https://
  • Padlock icon displayed in the address bar - indicates the server's certificate is trusted and the connection is secure.
  • A website can be configured to require HTTPS and reject or redirect plain HTTP requests.
