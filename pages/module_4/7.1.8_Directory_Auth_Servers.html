7.1.8 Directory and Authentication Servers

Overview

Networks must authenticate and authorize clients before allowing access to resources. Enterprise networks use directory servers to maintain a centralized database of user accounts.

SSO (Single Sign-On)
A user authenticates once to gain authorization for all compatible application servers on the network.

LDAP (Lightweight Directory Access Protocol)

Directory
A database where network resources are recorded as objects (like records) with attributes (like fields). Based on the X.500 standard.
LDAP
TCP/IP protocol used to query and update an X.500 directory. Supported by Windows Active Directory and open-source OpenLDAP.
Ports
TCP/UDP 389 (default, unencrypted). TCP/636 (LDAPS - TLS-encrypted).

AAA (Authentication, Authorization, and Accounting)

Consolidates authentication services across multiple access devices, eliminating the need for each device to store credentials locally.

Supplicant
The device requesting access (e.g., a user's PC or laptop).
NAS / NAP (Network Access Server / Network Access Point)
Network access appliances (switches, access points, VPN gateways). Also called AAA clients or authenticators. They forward credentials between the supplicant and the AAA server - they do not store credentials themselves.
AAA Server
The centralized authentication server, positioned within the local network. Validates credentials and issues access decisions.

RADIUS vs. TACACS+

RADIUS TACACS+
Full Name Remote Authentication Dial In User Service Terminal Access Controller Access Control System Plus
Protocol / Port TCP/UDP 1812 (auth), 1813 (accounting) TCP/49
Primarily Used For Authenticating users to a network Authenticating devices (routers, switches)

RADIUS Authentication Flow

  1. Step 1: RADIUS server and NAS (switch) are pre-configured with the same shared secret.
  2. Step 2: Supplicant connects to the network.
  3. Step 3: Switch instructs the supplicant to authenticate and blocks other network traffic.
  4. Step 4: Supplicant transmits a credential.
  5. Step 5: Switch forwards the credential to the RADIUS server.
  6. Step 6: RADIUS server validates the credential.
  7. Step 7: RADIUS server issues an Access-Accept.
  8. Step 8: Switch opens the network channel for regular traffic.
