7.5.2 Troubleshooting Networks (Part 1)

Common Network Failure Points

  • Cables - damaged, improperly seated, or faulty patch cords
  • NICs - failed hardware or bad/incompatible drivers
  • Switch/router ports - damaged ports, disabled ports, misconfigured settings
  • Wi-Fi - interference, misconfiguration, signal issues
  • Power problems - power blinks can wipe unsaved configurations
  • Driver problems - new/updated drivers that cause issues; rollback may be required
  • Configuration mistakes - human error (wrong IPs, gateway, VLAN, etc.)

SOHO Network Failure Points

A typical SOHO device combines a wireless access point, physical switch ports, and a router in one unit. Common failure points include:

  • Cabling — home cables are more likely to be moved, pulled, or damaged accidentally
  • Wi-Fi configuration — incorrect SSID or password on the AP or client device
  • Switch ports — ports can degrade or fail on the combo device
  • NICs — wired or wireless adapters on client devices can fail
  • ISP / outside the DMARC — line cuts, ISP equipment issues, or configuration problems on the provider side

Troubleshooting Process: Inside Out

Step Action
1 Test everything inside the private network first. Ping between wired computers, ping wireless devices, ping the default gateway.
2 If internal connectivity is confirmed but internet access fails, the issue is likely on the ISP side (outside the DMARC).
3 Contact the ISP if the problem appears to be beyond the DMARC (line cut, ISP equipment fault, provider-side config issue).

DMARC (Demarcation Point)

The boundary between the customer's private network and the ISP's infrastructure. Problems on the customer side are the technician's responsibility; problems beyond the DMARC belong to the ISP.

OSI Model Approach to Troubleshooting

Always start at Layer 1 (Physical) and work upward. Most network problems are resolved at the lower layers before reaching application-level issues.

Layer What to Check Tools / Actions
1 - Physical Cables, link LEDs, NIC hardware Visual inspection, cable tester, loopback ping, swap cable/port
2 - Data Link NIC driver, switch port status, port configuration Check switch config, enable/move port, update or roll back NIC driver
3 - Network IP address, subnet mask, default gateway, DHCP scope ipconfig /all, ping default gateway, check DHCP server scope
Upper layers Application faults, driver issues Reinstall application, roll back driver

Key Troubleshooting Tools

ping
Tests connectivity to a target IP. Use a loopback ping (ping 127.0.0.1) to test the local NIC. Ping the default gateway to confirm Layer 3 reachability. Ping devices hop by hop to isolate where connectivity breaks.
ipconfig /all
Displays IP address, subnet mask, default gateway, DNS servers, and other adapter settings. Confirms whether DHCP-issued configuration is correct.
tracert
Traces the route packets take to a destination, showing each hop. Useful for identifying where in the path communication fails.

Scope-Based Isolation

Before diving into physical checks, determine the scope of the problem:

  • Only one host affected - problem is likely local (cable, NIC, IP config).
  • Multiple hosts affected - problem is likely infrastructure (switch port, DHCP server, router, gateway config).
  • Other hosts can reach the target but one cannot - server/path is fine; focus troubleshooting on the affected host.

Real-world example: a DHCP scope configured with the wrong default gateway address caused all clients to receive incorrect gateway IPs, blocking all external access. Correcting the scope fixed the issue network-wide.
