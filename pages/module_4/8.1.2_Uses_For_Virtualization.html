8.1.2 Uses for Virtualization

Client-Side Virtualization

Runs on standard desktops/workstations where users interact directly with the virtualization host. Typically uses a Type 2 (host-based) hypervisor. Common use cases:

Use Case Description
Sandboxing Isolated VM environment for analyzing malware (viruses, worms, Trojans) without risk to the host or network.
Legacy software support Run an older OS as a VM to maintain access to software incompatible with a newer host OS.
Cross-platform testing Test applications under different OSs and resource constraints.
Training / lab environments Students practice on live OSs without affecting production. VM changes can be discarded to restore the original state for the next user.

Server-Side Virtualization

Deploys server roles as VMs. Primary benefit is server consolidation — a physical server typically uses only ~10% of its resources, so 8-9 additional server instances can run on the same hardware without compromising performance.

Desktop Virtualization (VDI)

VDI (Virtual Desktop Infrastructure)
Uses VMs to provision corporate desktops. Users connect via thin clients — low-spec devices that boot a minimal OS and connect to a VM on a server using a remote desktop protocol (Microsoft Remote Desktop or Citrix ICA).
Thin Client
A computer that relies on a centralized server for processing and storage instead of a local hard drive. Only handles display, audio output, and input device data transfer.
Connection Broker
Manages mapping of thin clients to their correct VM image; may use 1:1 mapping by machine name or IP address.
DaaS (Desktop as a Service)
VDI provisioned as a cloud service.

Benefits: simplified backups, easier support/troubleshooting, VM changes easily overwritten from a template, IT infrastructure can be offloaded to a third party.

Disadvantage: no local processing during server or network failures, potentially causing costly downtime.

Application Virtualization

Allows clients to access or stream applications from a server without local installation. Users always run the latest version; simplifies admin updates and maintenance.

  • Citrix Virtual Apps (formerly XenApp) — most widely used
  • Microsoft App-V — included in Windows Server
  • VMware ThinApp

Container Virtualization

Isolates resources at the OS level — no hypervisor required. Containers run through the host OS kernel, each allocated CPU and memory.

Virtual Machines Containers
Isolation level Full OS per VM (hardware emulation) OS-level (shared kernel)
Requires hypervisor Yes No (uses container engine, e.g., Docker)
OS kernel Each VM has its own kernel All containers share the host OS kernel
Cross-OS support Can run different OS families Must use the same OS kernel (e.g., cannot run Windows in a Linux container)
Weight Heavier (full OS per instance) Lightweight (app + libraries + env variables only)
Example product VMware, VirtualBox, Hyper-V Docker

Containerization is also used to implement corporate workspaces on mobile devices.
