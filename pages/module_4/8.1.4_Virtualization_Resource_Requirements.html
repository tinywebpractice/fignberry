8.1.4 Virtualization Resource Requirements

CPU: Virtualization Extensions

Feature Intel AMD
Virtualization Technology VT-x AMD-V
SLAT (Second Level Address Translation — improves virtual memory performance with multiple VMs) EPT (Extended Page Table) RVI (Rapid Virtualization Indexing)
  • Most virtualization software requires VT-x or AMD-V enabled. If disabled, VM performance suffers significantly.
  • Virtualization support may be disabled in BIOS/UEFI by default on some CPUs — verify and enable it.
  • Multiple CPU resources (multi-core, HyperThreading, multiple physical CPUs) greatly improve performance when running multiple guest OSs concurrently.
  • A 64-bit hypervisor can support 32-bit guest OSs. A 32-bit hypervisor cannot support 64-bit guest OSs.

System Memory (RAM)

  • Each guest OS requires RAM on top of what the host OS/hypervisor needs.
  • Example: Windows 11 requires at least 4 GB; a workstation running one Windows 11 guest needs at least 8 GB total RAM.
  • Running multiple guest OSs concurrently increases memory demands proportionally.
  • Development/testing VMs are less performance-critical and can tolerate lower RAM specs.

Mass Storage

  • Each VM's "hard disk" is stored as an image file on the host.
  • Most hypervisors use dynamically expanding disk images that grow as data is added.
  • Typical Windows VM: ~20-30 GB depending on version and installed applications.
  • Snapshots capture the VM's disk state at a point in time. Useful for rolling back changes during testing but consume additional space per snapshot.
  • In enterprise environments, VM disk images can be stored on a high-speed SAN (Storage Area Network), removing local disk space limitations.

Networking

  • A hypervisor can create a virtual network to allow communication between VMs, the host, and other hosts.
  • Enterprise virtualization platforms support configuring virtual switches and routers.
