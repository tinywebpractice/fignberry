8.1.5 Virtualization Security Requirements

Guest OS Security

  • Each guest OS requires regular patching and malware protection, just like a physical OS.
  • Patching individual VMs impacts performance — use a patched template image that is tested before deploying to production.
  • Running antivirus/IPS on every guest degrades performance. Use virtualization-aware security solutions managed at the hypervisor/host level instead.
  • Standard host antivirus cannot detect malware inside guest OSs. Scanning virtual disks from the host causes severe performance issues.
Rogue VMs / VM Sprawl
Uncontrolled deployment of unauthorized VMs leads to VM sprawl, complicating security and resource management. System management tools can detect and control rogue builds.
Logic Bombs
Malicious code inserted into VM images by rogue developers or contractors; a key reason to enforce strict controls over VM template development.

Host Security

  • The host is a single point of failure — if it goes down, all guest VMs go offline simultaneously.
  • Mitigations: high availability (automatically restart VMs on another host on failure) and power redundancy (UPS, backup generators).

Hypervisor Security

VM Escaping
A critical threat where malware on a guest OS exploits hypervisor vulnerabilities to access other guest VMs or the host itself. Mitigation: keep the hypervisor patched.

Cmdlet Purpose Key Switches
New-VM Creates a new VM; defines basic properties -Name, -Path, -MemoryStartupBytes, -Generation, -VHDPath, -VHDSizeBytes
