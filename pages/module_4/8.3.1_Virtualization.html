Virtualization

Modern hardware (multi-core CPUs, gigabit NICs, SSDs, large RAM) is powerful enough that most systems run well below capacity. Virtualization allows that unused capacity to be fully utilized by running multiple operating systems simultaneously on one physical machine.

The key software component is the hypervisor, which manages virtual machine instances and handles communication between guest OSes and physical hardware/drivers.

Hypervisor Types

Type Also Called How It Works Use Case
Host-based Type 2 Installed on top of an existing host OS; guest OSes run within the hypervisor layer Personal/home use, development
Bare metal Type 1 Installed directly on hardware with no host OS underneath; hypervisor + VM management software run directly on the machine Cloud environments, enterprise server farms

Virtual Machine Instances

  • Each instance gets its own allocated RAM, disk space, and network access
  • Guest OSes do not need to match the host OS - Linux, Windows versions, DOS, macOS, and server OSes can all run simultaneously
  • Instances can be added or removed dynamically without reinstalling the host
  • Resources are shared - too many instances degrade overall performance
  • New instances can be provisioned via API in minutes rather than days

Virtualization and the Cloud

  • Large server farms run bare metal hypervisors, hosting hundreds of virtual servers per physical machine
  • Virtual switches and load balancers also run within the virtual environment - no dedicated physical hardware required
  • Spinning up servers in minutes vs. days or weeks is the core advantage driving cloud scalability
  • All virtual resources behave like physical hardware to the guest OS
