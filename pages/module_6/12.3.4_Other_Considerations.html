12.3.4 Other Considerations

Overview

Before deploying new applications, their impact on the business, operations, and network devices must be assessed and mitigated. The IT department must maintain control over all third-party software. Unsanctioned software and devices (shadow IT) raise substantial operational and business risks.

Impact to Business

Licensing
Commercial software must be used within its license constraints, which typically limit the number of devices or users. Installing unlicensed software exposes a company to financial and legal penalties.
Support
Software may come with paid support (updates, security monitoring, technical assistance) or be supported internally. Either way, the impact on IT operations must be assessed.
Training
Complex apps can have substantial and ongoing user-training costs as new versions introduce interface/feature changes, and new employees require initial training. Internal support staff may also need technical training to maintain the application securely.

Impact to Operations

  • Large-scale deployments (hundreds of desktops) require automated tools to deploy, update, and support applications.
  • Network-based installer: Setup file is copied to a shared network folder; client computers run setup from the network. In Windows, Group Policy Objects (GPOs) can remotely install applications without manual administrator intervention.
  • Push deployment: Tools such as centrally managed antivirus suites can push the client or security sensor to each desktop remotely.
  • Network deployments and image pushes cause network congestion and increased latency. Organizations typically schedule these during non-critical times (overnight or weekends).
  • GPO deployment allows setup to run under a service account, so users do not need local administrator privileges. Write/modify permissions on application directories are restricted to administrator-level accounts, preventing unauthorized changes.
  • Users need read/execute permission on the application's installation directory. User-specific files and settings should be saved to the user's home folder/profile, not the application directory.

Impact to Device and Network

Threat / Risk Description Mitigation
Trojan Horse Malware whose true malicious purpose is concealed; designed to steal data or provide covert remote access once installed Install only from trusted sources; verify the installer is digitally signed by a reputable publisher
Virus-infected installer Setup file infected with a computer virus, intentionally or unintentionally Scan installer for malware; verify digital signatures and hash values
Resource overconsumption Software consumes more CPU, memory, or network bandwidth than anticipated Test in a lab environment before wide deployment
Compatibility problems Conflicts with other local or network applications Test in a lab environment; research known compatibility issues
Unpatched vulnerabilities Could allow worm malware to propagate and crash the network Research security advisories; verify developer has a robust patch process

Best practice: test all applications in a lab environment before deploying more widely. Research security advisories associated with the software and confirm the developer has a robust approach to identifying and resolving security issues.
